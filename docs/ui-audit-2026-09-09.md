# Mobile UI audit fixes — 2026-09-09

Rebaselined M1–M6 against development `20b0cd6`. All six findings are addressed; native device validation remains outstanding.

- **M1:** [App.tsx](../App.tsx) submits one atomic `POST /api/qa-reports/submit`, uses the returned persisted report, and projects `qaReports` on bootstrap. Removed local-only reports and separate task/follow-up/blocker writes. A failed command keeps the draft. A successful command followed by failed refresh stays acknowledged, avoiding duplicate retry. Old-session completions cannot update the current UI. Leads, mentors and admins can submit; only mentors/admins see mentor approval. [App integration test](../src/app/__tests__/qaSubmission.test.ts) exercises command failure, acknowledged success with refresh failure, one-command routing, and report reload. Platform owns transactional workflow/restart verification.
- **M2:** [Fields](../src/ui/editorFieldWidgets.tsx), [chips](../src/ui/selectionWidgets.tsx), and [dropdowns](../src/ui/selectionFieldWidgets.tsx) expose translated labels, roles, checked/selected/expanded/disabled state. [Executable controls tests](../src/ui/__tests__/editorControls.test.ts) query their accessibility semantics.
- **M3:** [EditorModal](../src/ui/editorWidgets.tsx) owns a synchronous in-flight guard and disables save/delete/cancel plus draft editing until completion. Busy labels and disabled appearance communicate progress. Rejected saves retain draft/retry; closing clears stale errors. [Controls tests](../src/ui/__tests__/editorControls.test.ts) cover repeated taps, competing actions, delayed editing, failure and reopen.
- **M4:** [QA editor](../src/app/editorModals/QaReportEditorModal.tsx) and [work-log editor](../src/app/editorModals/WorkLogEditorModal.tsx) use roster-name checkboxes storing IDs. [App.tsx](../App.tsx) rejects participants absent from the latest roster instead of silently dropping them. [Controls tests](../src/ui/__tests__/editorControls.test.ts) verify name/ID selection behavior.
- **M5:** [Responsive metrics](../src/ui/responsive.ts) and [shared styles](../src/ui/styles.ts) enforce 48-unit minimum controls/chips. Search uses minimum height, allowing content to grow. [Controls tests](../src/ui/__tests__/editorControls.test.ts) cover compact-to-tablet metric widths and labeled search.
- **M6:** [TaskQueueScreen](../src/screens/tasks/TaskQueueScreen.tsx) renders at most 30 tasks per page, preserving section order/counts and existing filters. Page selection resets on filter changes and clamps when results shrink. [Large-queue component test](../src/screens/tasks/__tests__/TaskQueuePagination.test.ts) exercises page navigation, reset and shrink. Measured actual React Native development renderer: 500 tasks mounted 500 rows / 1717 ms before; 30 rows / 199 ms after. These local Jest measurements establish bounded mount work, not native frame-rate claims. Pagination was chosen over rebuilding the application scroll shell because it bounds the demonstrated work with less ownership change.
